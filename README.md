## PocketBase — новый сервер

Схема, серверные операции и проверка реальной SQLite-базы готовы для локального подключения.
Версия PocketBase — **0.40.5**. Бинарник и `pb_data` не публикуются в Git.

Первый терминал (если старый процесс PocketBase уже работает, остановите его через Ctrl+C):

```powershell
Set-Location -LiteralPath 'C:\Users\Asus F15\flutter_projects\pharmacy_project\backend\pocketbase'
.\pocketbase.exe serve
```

При запуске автоматически применяются миграции коллекций и однократная загрузка примеров.
Проверка: http://127.0.0.1:8090/api/pharmacy/__health.

Второй терминал, из корня Flutter-проекта:

```powershell
flutter run -d chrome --web-port=5555 --dart-define=API_BASE_URL=http://127.0.0.1:8090/api/pharmacy
```

Зарегистрируйте пользователя в приложении. Для первого администратора откройте панель
http://127.0.0.1:8090/_/, найдите его в `pharmacy_users` и измените **только** `role` на `admin`.
Затем выйдите из приложения и войдите снова. Аналогично назначается `pharmacist`.
Superuser панели не используется для входа в приложение. Старые учебные пароли мок-сервера
не переносятся; начальная миграция создаёт только каталог, не пользователей.

Подробности: [backend/pocketbase/README.md](backend/pocketbase/README.md).

## Предыдущий сервер — Node.js

Нужны Flutter и Node.js 22+. У сервера нет npm-зависимостей.
Команды выполняются из корня проекта в двух терминалах.

Первый терминал:

```powershell
node mock-server.js --port 8080 --origin http://localhost:5555
```

Проверка: http://localhost:8080/api/__health — ответ `{"status":"ok"}`.

Второй терминал:

```powershell
flutter pub get
flutter run -d chrome --web-port=5555 --dart-define=API_BASE_URL=http://localhost:8080/api
```

`--origin` должен точно совпадать с адресом вкладки, включая порт.
`localhost` и `127.0.0.1` — разные источники. При смене API-адреса
перезапустите Flutter с новым `--dart-define`.

## Вход и роли

После обновления кода перезапустите сервер: старый процесс не поддерживает новые адреса авторизации.

| Роль | Логин | Учебный пароль |
| --- | --- | --- |
| Пользователь | customer | Customer123! |
| Фармацевт | pharmacist | Pharmacist123! |
| Администратор | admin | Admin123! |

Регистрация создаёт только обычного пользователя. Фармацевт оформляет бронирования,
выдаёт/отменяет их и работает с пользователями аптеки. Пользователь просматривает свои
бронирования и один раз продлевает срок получения на три дня. Администратор управляет
учётными записями и ролями, восстанавливает/физически удаляет записи и видит статистику.
Разделы ролей не образуют иерархию: администратор не заменяет фармацевта.

Бронирование уменьшает свободный остаток сразу; отмена возвращает упаковки, выдача
не списывает их повторно. После истечения срока фармацевт должен отменить либо закрыть
бронь вручную. Корзины, оплаты, доставки и отдельной сущности покупателя нет.

Сессия сохраняется в SharedPreferencesAsync (в браузере — localStorage). Пароли клиент
не сохраняет; сервер хранит scrypt-хеши. Access JWT обновляется через refresh-токен;
роль и права сервер берёт из собственной записи пользователя. Выход отзывает сессию.
Без действий — выход через 180 секунд, предупреждение за 30 секунд. Общий срок — 1 час.
Перезагрузка страницы или refresh не начинают этот срок заново.

Для проверки короткого access-токена (войдите заново после запуска):

```powershell
node mock-server.js --port 8080 --origin http://localhost:5555 --ttl 60
```

Для быстрой проверки общего срока можно добавить `--session-ttl 120`.
`--idle-ttl` меняет срок бездействия сервера и клиента; при обычной сдаче оставьте 180.
Имеющиеся сессии имеют срок, записанный при входе: после смены параметров войдите заново.

Все 18 пунктов и инструкция подмены роли из пункта 17 —
[docs/pr5-auth-report.docx](docs/pr5-auth-report.docx), исходник —
[docs/pr5-auth-report.md](docs/pr5-auth-report.md).

Это учебная реализация: HTTP, demo-пароли и токены в localStorage нельзя переносить
в production без HTTPS, защищённого хранения, усиления защиты от XSS и ограничения попыток входа.

## Хранение

Источник данных — сервер. Начальный каталог: `server/seed-data.json`.
Каждое успешное изменение сохраняется в `.mock-data/catalog.v1.json`;
при следующем запуске сервер читает этот файл. Изменения переживают
обновление вкладки, перезапуск браузера и сервера. Физически удалённые
записи не возвращаются из начального набора.

Клиент держит текущую страницу каждого посещённого раздела, открытые
карточки и кэш справочников. Старые изменения из хранилища браузера ПР3
автоматически не переносятся. Локальный репозиторий сохранён для тестов
прежнего этапа, но в приложении подключён только API-репозиторий.

Для демонстрации без изменения основного каталога:

```powershell
node mock-server.js --port 8080 --origin http://localhost:5555 --data-file .mock-data/demo.json
```

`--no-persist` явно отключает сохранение: изменения живут до остановки
такого экземпляра сервера. Это не режим по умолчанию.

## Демонстрация ошибок

- 500: http://localhost:5555/drugs?__fail=500
- Задержка 1500 мс: http://localhost:5555/drugs?__delay=1500
- Недоступность: остановите сервер через Ctrl+C и обновите список;
  после запуска сервера нажмите «Повторить».
- 422: создайте препарат с существующим номером `ЛП-001201`, остальные
  поля заполните корректно.
- 409: войдите фармацевтом и в карточке препарата с нулевым остатком нажмите «Отпустить».
  В исходном каталоге это «Парацетамол», `/drugs/1`.

Диагностические параметры передаются API из URL. Уберите их из адреса
или нажмите «Сбросить» для обычного режима. HTTP 500 не повторяется
автоматически: повторы — только при сетевом сбое чтения, до трёх попыток.
