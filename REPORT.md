# Отчёт по практической работе 2

## Предметная область

Библиотечные сущности из задания адаптированы к аптеке:

- `Book` → `Drug` («Препарат»), 24 начальные записи;
- `Author` → `Supplier` («Поставщик»), 10 начальных записей.

Обе модели неизменяемые и содержат `copyWith`. В ПР2 данные находились в отдельных in-memory репозиториях. В текущей версии они сохраняются локальным репозиторием в браузере. Экраны работают через `ChangeNotifier`, прямых обращений виджетов к репозиторию нет.

## Исправление ошибки `deleteMany`

В исходном примере предикат был записан так:

```dart
_books.indexWhere((b) => b.id == id && !b[i].isDeleted)
```

Переменная `b` в этом выражении — один объект модели, а не список, поэтому индексировать её через `[i]` нельзя. Кроме того, индекс `i` вычисляется самим вызовом `indexWhere` и внутри предиката ещё не определён. Исправленный вариант проверяет текущий объект напрямую:

```dart
list.indexWhere((item) => item.id == id && !item.isDeleted)
```

Та же корректная логика используется для всех пяти сущностей. Множественное удаление является логическим: каждой найденной активной записи назначается `deletedAt`.

## Реализованные возможности

- Поиск препаратов по названию и регистрационному номеру; поставщиков — по названию, контактному лицу и стране.
- Одновременная фильтрация препаратов по категории, поставщику и диапазону года производства.
- Логическое и физическое удаление, показ удалённых записей и восстановление.
- Множественный выбор со счётчиком и подтверждением удаления.
- Адаптивное представление: таблица от 600 px, карточки при меньшей ширине.
- Сервероподобная пагинация по 10, 25 или 50 записей, переходы на первую, предыдущую, следующую и последнюю страницы.
- Сортировка по заголовкам не менее трёх колонок. Общая таблица реализована как `EntityTable<T>`.
- Поиск запускается через 400 мс после окончания ввода.
- Поиск, фильтры, сортировка, номер и размер страницы, а также показ удалённых отражаются в query-параметрах URL и восстанавливаются при открытии ссылки.

## Следующий этап: формы и сохранение

Добавлены `Manufacturer`, `Category`, `SupplierLicense`. Все пять сущностей имеют
`copyWith`, `toJson`, `fromJson`, список, карточку, общую форму создания и
редактирования, поиск, фильтры, сортировку, пагинацию и оба вида удаления.

JSON всего каталога хранится под ключом `pharmacy.catalog.v2` в
`shared_preferences` (на Flutter Web — в хранилище браузера). При запуске
репозиторий сначала читает сохранённую версию. При отсутствии данных он создаёт
начальный каталог из `seed_data.dart` и сохраняет его. Каждая операция записи
сохраняет обновлённый каталог до изменения видимого состояния. Если формат
сохранённых данных повреждён или имеет другую версию, приложение загружает
начальный каталог и показывает предупреждение.

Связи представлены так:

- многие к одному: `Drug.manufacturerId` и `Drug.supplierId`;
- многие ко многим: `Drug.categoryIds` и `Supplier.manufacturerIds`;
- один к одному: у поставщика не более одной `SupplierLicense`, поля лицензии
  редактируются вместе с полями поставщика.

Удаление производителя запрещено, если на него ссылаются препараты;
сообщение содержит число таких препаратов. Выбор производителя в форме
препарата ограничивает выпадающий список поставщиков. Все варианты для
выпадающих списков приходят из репозитория через `CatalogStore`.

Проверки полей находятся в `lib/core/validators.dart`. Ошибки обязательности,
длины, формата адреса почты, диапазонов и уникальности показываются у
соответствующего поля. Форма использует `PopScope` для предупреждения о
несохранённых изменениях. Общая разметка и обработка полей находятся в
`lib/widgets/catalog_form.dart`. Предупреждение при уходе действует как для
кнопки возврата, так и для перехода через `go_router`: `PopScope` дополнен
проверкой выхода из маршрута.
