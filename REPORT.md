# Отчёт по практической работе 2

## Предметная область

Библиотечные сущности из задания адаптированы к аптеке:

- `Book` → `Drug` («Препарат»), 24 начальные записи;
- `Author` → `Supplier` («Поставщик»), 10 начальных записей.

Обе модели неизменяемые и содержат `copyWith`. Данные находятся в отдельных in-memory репозиториях. Экраны работают только через `ChangeNotifier`, прямых обращений виджетов к репозиториям нет.

## Исправление ошибки `deleteMany`

В исходном примере предикат был записан так:

```dart
_books.indexWhere((b) => b.id == id && !b[i].isDeleted)
```

Переменная `b` в этом выражении — один объект модели, а не список, поэтому индексировать её через `[i]` нельзя. Кроме того, индекс `i` вычисляется самим вызовом `indexWhere` и внутри предиката ещё не определён. Исправленный вариант проверяет текущий объект напрямую:

```dart
_drugs.indexWhere((drug) => drug.id == id && !drug.isDeleted)
```

Та же корректная реализация использована для поставщиков. Множественное удаление является логическим: каждой найденной активной записи назначается `deletedAt`.

## Реализованные возможности

- Поиск препаратов по названию и регистрационному номеру; поставщиков — по названию, контактному лицу и стране.
- Одновременная фильтрация препаратов по категории, поставщику и диапазону года производства.
- Логическое и физическое удаление, показ удалённых записей и восстановление.
- Множественный выбор со счётчиком и подтверждением удаления.
- Адаптивное представление: таблица от 600 px, карточки при меньшей ширине.
- Сервероподобная пагинация по 10, 25 или 50 записей, переходы на первую, предыдущую, следующую и последнюю страницы.
- Сортировка по заголовкам не менее трёх колонок. Общая таблица реализована как `EntityTable<T>`.
- Поиск запускается через 400 мс после окончания ввода.
- Поиск, фильтры, сортировка, номер и размер страницы, а также показ удалённых отражаются в query-параметрах URL и восстанавливаются при открытии ссылки.
